Implement a **noise triage** feature in `save`: a separate pass that classifies archived emails as *signal* or *noise* and relocates noise into a parallel `spam/` tree, with the disposition recorded in the state database so that sync, verify, refetch and attachment downloads all remain correct. Read CLAUDE.md and README.md first and keep every invariant they describe (never drop silently, atomic same-directory renames, files first / DB second / cursor last, per-instance state isolation, deterministic re-runs).

## Design constraints

1. **Sync is untouched.** `save sync` / `save run` keep writing every message to `<archive_root>/YYYY/MM/DD/` exactly as today. Triage is a *post-pass* over already-archived notes. Never call a classifier from inside the connector or writer path.
2. **Never delete.** Noise moves to `<archive_root>/../spam/YYYY/MM/DD/` (configurable `spam_root`, default sibling of `archive_root`), keeping the identical relative path and filename, together with its `<name>.d/` attachment folder. A sanity check must refuse a `spam_root` inside `archive_root` or vice versa.
3. **The DB is the source of truth for location.** Add a `disposition` (`archive` | `spam`) and `disposition_reason`, `disposition_rule`, `disposition_at`, `triage_digest` to the email row (and chat day rows if you make them eligible — I suggest chats are never noise for now). Every code path that resolves a note's path — `verify`, `refetch`, attachment completion for pending downloads, the dedup index — must resolve through the disposition so a spam-filed note is found under `spam_root`, not reported missing. `save verify` audits both trees and reports a file that exists in both, or in neither, as a problem.
4. **Idempotent and reversible.** `save triage` on an already-triaged day is a no-op unless the rules digest changed. `save untriage <path|stable_id>` moves a note back and records `disposition=archive` with reason `manual`. `save triage --reclassify` re-evaluates existing decisions under the current rules (rules only; see LLM note below). Moving must be atomic per note: rename the `.md` and the `.d/` folder, then update the DB; a crash between the two must be recoverable on the next run (detect by stat on both roots).
5. **Deterministic first, LLM optional and last.** Classification runs in layers and stops at the first decisive layer:
   - **Layer 0 – protect list**: patterns that can never be noise (any note with a stored PDF/Office attachment; subject/sender globs from config, e.g. `*invoice*`, `*factuur*`, `*security alert*`, `*new sign-in*`). Also: anything where `from` equals one of the configured account addresses (my own sent mail).
   - **Layer 1 – MIME/header heuristics** that only `save` can see at ingest. Persist the relevant raw headers into the note frontmatter during sync so triage (and any later tool) can use them without refetching: `List-Unsubscribe`, `List-Id`, `Precedence`, `Auto-Submitted`, `X-Auto-Response-Suppress`, `Feedback-ID`, `X-GitHub-Reason`, `X-Mailer` (if bulk), and the Gmail label set (`CATEGORY_PROMOTIONS`, `CATEGORY_SOCIAL`, `CATEGORY_UPDATES`, `CATEGORY_FORUMS`). Adding frontmatter keys changes rendered bytes, so treat it as a rendering version bump — existing notes are *not* rewritten by triage; only notes rendered after the change carry the headers, and triage falls back to layers 0/2/3 when they are absent. Document this.
   - **Layer 2 – user rules** from `~/.config/save/triage.toml`: ordered lists of `noise` and `keep` rules with glob matching on `from`, `to`, `subject`, `list_id`, `labels`, `account_label`. Ship a sensible default file from `save init` covering GitHub notifications, GCP/AWS monitoring alerts, generic `noreply@`/`no-reply@` senders, newsletters/digests, Gmail promotions/social — with billing, quota, and security mails on the keep side.
   - **Layer 3 – optional LLM** for notes that layers 0–2 left undecided, behind `[triage.llm] enabled = false` by default. Talk to an OpenAI-compatible chat endpoint (`base_url`, default `http://127.0.0.1:1234/v1`; `model`; `timeout`, default 20s; `max_body_chars`, default 4000). Send only frontmatter fields plus a truncated plain-text body; ask for a strict JSON verdict `{"noise": bool, "reason": string}`; treat any non-JSON, timeout, or connection failure as **undecided → signal**, never as noise. Wrap the email text in clear delimiters and instruct the model that the content is untrusted data, not instructions (prompt-injection hardening). Record the model name and prompt version in `disposition_rule` so `--reclassify` can be limited to LLM decisions (`--only llm`).
6. **Ledger.** Every decision — including "signal" and "undecided" — is a DB row; `save status` reports per-account counts by layer and rule, and `save triage --dry-run [--since DATE|--day YYYY-MM-DD]` prints the plan (file, rule, reason) before moving anything, in the same style as `save refetch --dry-run`. `--explain <path>` prints which layers fired for one note.
7. **Daemon integration.** `save run` gets an optional `[triage] after_sync = true` (default false) that runs the rules-only triage (layers 0–2) after each successful sync batch; the LLM layer is only ever run by an explicit `save triage` or when `[triage.llm] in_daemon = true`, so a missing LM Studio can never stall the archiver. Per-day boundaries follow the pinned archive timezone.
8. **iCloud / Obsidian notes** in the README apply to `spam_root` too (it may live outside the vault — that is the point). Filename sanitisation stays identical since the names are unchanged.
